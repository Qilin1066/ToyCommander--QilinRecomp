# Changelog

All notable changes to this project are recorded here, in the format of [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Past entries are kept as written, never rewritten.

This is Toy Commander's changelog; Toy Racer's is `toyracer/CHANGELOG.md`. A change to code both games share is recorded in both. Versions are tagged `toycommander-vX.Y.Z` (`vX.Y.Z` before the two games shared a repository); the number lives only in `CMakeLists.txt` (`QILIN_TOYCOMMANDER_VERSION`, the project's version). While the recompiler and runtime are being built, a minor bump (0.**x**) marks a milestone and a patch bump (0.x.**y**) a fix. 1.0.0 will be the first build that plays the game.

## [Unreleased]

### Changed
- **Less work in the sound driver**: its per-frame pass brings the sound up to date once, not once or twice for each playing channel. Not timed yet.
- **One copy of the natives both games share**: 35 small replacements (memory fill and copy, the allocator's entry points, the console settings, timer and cache calls, the interrupt set-up) that each game had its own copy of now live once in `shinobi/src/library.cpp`, at each game's addresses. No change in behaviour.
- **Cheaper calls to native code**: each replaced function finds its native once instead of on every call, and the release build no longer compares every register before and after it (development builds still check). Not timed yet.
- **Faster loading**: the disc's data is read a request at a time with its file kept open, instead of opening the file again for every 2 KB sector, and copied into memory in one go. Not timed yet.
- **Less register traffic in the recompiled code**: a function stores back only the registers it changes, and after a call reloads only those the callee may change (3% to 6% fewer of each across the game's code). Not timed yet.
- **Less data sent to the GPU a frame**: a smooth-shaded strip's vertices are sent once and its triangles as indices, instead of three copies of each inner vertex (a quad's data 26% smaller, a ten-vertex strip's 51%). The same pictures. Not timed yet.
- **Faster texture decoding**: a twiddled texture's texels are placed by two small tables a level rather than a loop over the bits for each texel (16-bit, paletted and compressed textures). The same pictures (checked for every size). Not timed yet.
- **Faster calls through pointers**: an indirect call's target is looked up in a small cache before the function table's binary search, so a repeat (the usual case: object and callback tables) is one compare. Not timed yet.
- **Fewer loads in lifted code**: each function keeps guest memory's base in a local rather than reading the global again after every store (a store through a byte pointer could, as far as the compiler knows, change it). Not timed yet.
- **Calls into native code save fewer registers too**: each native's registers are worked out from its source (50 of Toy Commander's 61 natives, 70 of Toy Racer's 83), so a call to one, or to code that reaches only such natives, stores and reloads only those; a native that changes any other register stops the game, naming it. Stores and reloads around a direct call: 22.5 on average in Toy Commander (23.7 before, 33.8 originally), 22.1 in Toy Racer (25.3, 34.1). Not timed yet.
- **The renderer builds a scene while the GPU finishes the previous one** (not timed yet): it waited for the GPU before converting the scene's vertices and decoding its textures; now it waits only when it reaches what the GPU's work in flight uses.
- **Less work around calls between lifted functions** (not timed yet): a direct call stores and reloads only the registers the function called (and what it calls) can read or change, instead of all of the caller's: 30% fewer of those around Toy Commander's 11,223 calls, 26% around Toy Racer's 12,561. The same code otherwise.
- **The two games' system layers are one copy** (`shinobi/src`): the start-up and the replacements of Shinobi's allocator, interrupt chains, clock, GD-ROM calls and threads, which each game had its own copy of, differing only in addresses; each game now gives its addresses in its `build.hpp`. The same natives at the same addresses as before.
- The recompiler keeps each supported build's facts (regions, replaced functions, known entries, data blocks, indirect call tables) in one record, found once by the boot file's hash; the lifted code is byte for byte what it was.

### Added
- **Texture packs**: `dump_textures = true` saves every texture the game draws to `textures/dump` in the data folder as `<width>x<height>_<hash>.png`; PNG files so named in `textures/load` (or folders in it) are drawn in those textures' place, at any size (`texture_packs`, on by default). Both on the menu's Graphics page, with a Reload button that reads the folder again while the game runs; a texture is hashed only while there are replacements or a dump, and replacements are read on a thread of their own, so a large pack doesn't stall the game (the original shows until its replacement is ready).
- **Multisample anti-aliasing**: `msaa = 1, 2, 4 or 8` in the settings file and "Anti-aliasing (MSAA)" in the menu's Game page, at most what the GPU has, changed while the game runs. The `desktop` preset has 4x; `original` and `low-end` none. Polygons' edges are smoothed; the translucent list's per-pixel sort blends after the samples are resolved, so its own edges stay as they were.

### Fixed
- **Two crashes that could have happened are fixed**: an error in the sound driver's work on the mixer thread now gives a report instead of a silent exit, and clearing memory through RAM's uncached addresses no longer crashes.
- **The console flash memory's save history keeps whole saves**: a copy was kept before each 64-byte write, so one save filled the history's five copies with itself half-written; now one copy is kept a save, as the memory card does. (Shared code: Toy Commander doesn't use the flash memory.)
- **CD music no longer reads the disc with the sound lock held**: the next 0.2 seconds are read ahead in the background from a track file kept open, instead of opening the file and reading while the game's thread waits for the sound chip.
- **The texture cache lets go of textures unused for a while** (1,200 renders): it kept every texture ever drawn, each with its own GPU memory and descriptor sets, which over a long session could reach the device's allocation limit.
- **Less memory traffic a render**: a render draws, stores and resolves only its own area, instead of loading and storing the whole picture; with multisampling, one shared multisampled image whose samples are never stored, instead of one kept per frame buffer for nothing.
- **The sound chip's interrupt** is no longer raised from the mixer thread into the system bus's status register while the game's thread reads and acknowledges it (it could be lost); it waits in a mailbox the game's thread takes in.
- **A stop's report and exit code** are no longer at risk at the end: the program ends without static destructors while the sound mixer and the display's threads still run (after a stop, at the game's end and on a fatal error).
- **`qilin lift` fails if any function wasn't lifted**, and the FPSCR mode pass stops `qilin` if it doesn't settle, instead of going on with modes that could be incomplete.
- **Builds with zig's Clang on Windows**: CMake no longer scans the C++ sources for modules (the project has none), which needed `clang-scan-deps` and stopped the build before it compiled anything.
- The launcher check's file hashes resolve a relative path against PowerShell's current folder, not the process's.
- **Widescreen from the first frame**: the picture stayed 4:3 until the game's options were changed or loaded from a save (the game widens its camera only then); it's now widened from the start, and follows the window when it's resized. Toy Commander's in-engine introduction and demo play checked at 21:9.

## [0.12.0] - 2026-11-22

### Fixed
- A controller that pressed while all four ports were full remains eligible for a vacant port. It no longer needs another unplug/replug; connected players keep their assignments.
- Rumble uses a renewable 300 ms lease rather than a 60-second command. Constant-strength vibration renews every 100 ms; stalled producers expire, disconnect/order reset stops motors, and non-finite strengths stop vibration.
- Destroying a display releases its own video/gamepad subsystem references rather than calling global `SDL_Quit`, preserving audio owned by another component.
- Missing playback devices and recoverable stream-operation failures no longer terminate the game. Output is retried at most once per second, stale queued sound is discarded, and saved volume/mute settings are applied before restarting playback. Stream lifecycle is serialised separately from the callback's SDL lock; callback errors are reported on the originating thread.
- Save history refuses linked folders that the restore validator would reject. Snapshot inspection/listing/pruning failures are reported instead of silently succeeding. Restore requests are bounded to 1024 bytes and accept UTF-8 BOMs/CRLF while still rejecting multiple lines or embedded NULs.

### Tests
- Added real SDL startup-failure/recovery and subsystem-reference checks alongside the concurrent callback/format/volume stress test.
- Extended the graphics-backed pad test with five-controller promotion, rumble renewal/expiry and audio ownership across display destruction. Linux CI requires it to run.
- Added linked-history, Windows-edited restore-request and oversized-request regressions. [Validation record](docs/validation-0.12-0.5.md); a complete real-disc playthrough remains unverified.

## [0.11.0] - 2026-11-22

### Fixed
- The Windows launcher hashes files through streamed .NET SHA-256, including headers, compiler, manifest and launcher content. Runtime-only updates force a link even with older timestamps; header/compiler/CPU changes invalidate compiled objects. `-Rebuild` cleans generated outputs, and choosing a disc on the quick path remembers it.
- Windows command lines are decoded from UTF-16. Disc, CUE track names, lift/extraction/output folders, save directories and menu paths use explicit native/UTF-8 conversion. New launches retain literal Unicode and shell metacharacters; stdout and stderr go to `run.log` and `run-errors.log`.
- VMU packet writes check bounds, the existing image size, seek, write, flush and close. Failed opens no longer fall back to truncating an existing file. Card and flash loads distinguish missing files from unreadable/malformed ones and bound reads to the image size.
- Settings, flash and save-history copies share checked, flushed file storage with unique temporary files and replacement on success. Failed copies preserve the destination. Settings accept UTF-8 BOMs and refuse to overwrite unreadable existing files with defaults.

### Tests
- Added storage tests for Unicode paths, bounded reads, packet writes, malformed images, multi-chunk copies, copying to self, failed replacements and Windows locked destinations. Settings/history tests cover Unicode folders, repeated replacement and BOMs.
- Windows CI requires real-Ninja launcher checks for both games: stale timestamps, header/compiler/CPU changes, unchanged reuse, forced rebuild, locked-update recovery, Unicode child arguments and the real recompiler's Unicode input/output paths.
- Added optional `QILIN_SANITIZE` for GCC/Clang. [Validation record](docs/validation-reliability-2026-11-22.md); no complete-game compatibility claim is made.

### Added
- **Movies are never stretched**: they're 4:3 pictures, so they're shown at 4:3 even in the game's 16:9 mode (the movie player is now a native, so the port knows when one is on screen).
- **The picture as wide as the screen**: the game's camera is widened as far as the screen is wider than 4:3 (16:9, 21:9, up to three times as wide) and the scene drawn that wide; the HUD and the menus' text keep their shape, in the middle. Nothing is stretched, and the movies stay 4:3. The game's own 16:9 option no longer changes anything.

## [0.10.0] - 2026-11-22
The game runs into its first mission and is played there with a controller: from the movies through the menus, drawn by the Vulkan 1.3 renderer with everything the PowerVR2 draws, with sound, CD music, saves, the settings menu, four controllers and the Jump Pack; Toy Racer joins it in this repository.

### Added
- **The translucent list sorted for each pixel** in auto-sort mode, as the hardware does: where translucent surfaces cross (smoke, glass, effects in Toy Commander's missions) each pixel blends them from the farthest. Devices without fragment-shader atomics keep the sort by triangle.
- **CI runs the graphical tests**: on Linux, under Xvfb and Mesa's software Vulkan, the renderer's, the Vulkan layer's and the pads' tests run on every push instead of skipping (`QILIN_REQUIRE_GRAPHICS=1` makes a skip a failure), as in Punch-Out's CI.
- **The saves' history** (from Punch-Out's): before the memory card or the console's flash memory changes, a copy is kept (the five latest of each); the menu's Game page lists them and can restore one and restart. The flash memory is now written through a temporary file, so a crash mid-write leaves the old one.
- **A modifier volume's user tile clip**: the volume counts only inside (or outside) its clip, for the opaque volumes (in the stencil) and the translucent ones (in the fragment shader's test); the render test checks both.
- **Controllers take their ports by their first press**: a virtual pad or a wheel listed first no longer takes port A from the real controller; a controller plugged in to replace an unplugged one takes its port; the menu shows each port's controller and can choose them again.
- **From Punch-Out's later work**: the sound queue that can't come to lag the picture (bounded, emptied by SDL's callback as the device plays; a new test runs it under SDL's real callbacks); input and rumble ignored while another window has the keyboard; settings for anisotropic filtering (the textures the game filters; 16x in the desktop preset), rumble strength, volume and muting when unfocused, in the file and the menu.
- **The rest of the PowerVR2's drawing** (`renderer.cpp`, `pvr.frag`, `ta.cpp`): the two-volume mode (a polygon's second volume drawn inside the modifier volumes, opaque, punch-through and translucent), vertex fog, the fog table's second mode, the colour clamp and the user tile clip. The render test checks each. Neither game's scenes so far use them.
- **Table fog is drawn** (`renderer.cpp`, `pvr.frag`): how the PowerVR2 picks a fog value from a pixel's depth was measured against the emulator as a black box (`qilin_dcref --fog`, a probe that sets the chip up itself and reads its renders back), and our own definition (`renderer::table_fog`) agrees with all 4,200 bands it drew, to within the 16-bit format's rounding. Polygons in fog mode 0 now go towards the fog colour by the table's value at each pixel's depth; the render test checks it. Nothing changes in the scenes seen so far, whose tables leave it invisible.
- **Fog is reported only where it could show**: table fog whose table is 0 everywhere has a fog factor of 0 at every depth, so drawing those polygons unfogged is already exact (Toy Racer's races). Both games' menus have a table with only its first entry set, which the renderer still reports, because how depth picks an entry is still to be measured against the emulator.
- **`tools/check/check_natives.py`**: checks that every replaced function a game's lifted code can reach has a native, from the lift's output and the game's sources (Toy Commander: 51 reachable, all with natives).
- **The console's flash memory** (`dreamcast/src/flash.*`): the boot ROM's four flash calls over 128 KB kept as `flash.bin` in the data folder, erased until a game formats a partition with its own code. Toy Racer's game uses partition 2; Toy Commander's doesn't call it.
- **Every byte of Toy Racer's boot file accounted for**: 5,140 functions, 4,053 lifted, 1,087 replaced, none left, and 0 unknown bytes in every region (`docs/toyracer/code-analysis.md`, "Every byte"). Three general changes came with it (`docs/recompiler-core.md`, "Three more rules from Toy Racer"): a layout's entry is tried even after a pointer guess at the same address failed; filler shorter than 32 bytes that ends on a 32-byte boundary is padding; and the FPSCR mode pass follows a branch into a delay slot, so the instructions after such a slot get a proven mode. Toy Commander's lift output is unchanged.
- **Toy Racer's own sound driver** (`dreamcast/src/aica.cpp`): Toy Racer's `AUDIO64.DRV` is version 1.90h.2, Toy Commander's 1.80d.2. The stand-in now knows both, from the offsets table the installed image publishes, and stops on any other: 1.90's records are elsewhere in sound RAM, its open closes first, its level is the total level, its sends set the direct level, and its stops drop events (`docs/runtime.md`, "Two versions of the driver"). Position events (commands `0x92` and `0xAD`) are now done as both drivers do them, posting the port's number as a message when the channel passes them; Toy Racer uses them, and stopped at its first one.
- **The lift step quotes its paths**: a Redump dump's name has parentheses and commas, which broke `-DQILIN_<GAME>_BOOT=<the .cue>`.
- **One repository for Toy Commander and Toy Racer, a program and a release for each** (the owner, 2026-11-21: "one repo, two releases"): the code both games share is `dreamcast/` (the hardware the port provides, the renderer, sound, the controller, memory card and Jump Pack, the settings file and menu), each game's own is `toycommander/src/` and `toyracer/src/`, and the recompiler knows both builds (`qilin info`, `layout`, `lift`). `qilin` now also takes a disc's `.cue` wherever it takes a boot file, reading the boot file from the dump.
- **A Windows download for each game** (`tools/player-kit`, `.github/workflows/player-kit.yml`, as Punch-Out's): `ToyCommander--QilinRecomp-X.Y.Z-windows-x64.zip` and `ToyRacer--QilinRecomp-X.Y.Z-windows-x64.zip`, nothing from the game in either. Unpack, double-click `Play <game>.bat`, choose your own dump's `.cue`: the bundled recompiler lifts its boot file and the bundled compiler (LLVM-MinGW) links it with the prebuilt rest of the game, once. Each game's tag builds and attaches its own.
- **Each game's program is checked without its disc**: its whole program but the lifted code is the library `<game>_game`, linked in every build with an empty function table (`<game>_link_check`), so CI compiles and links both games with every compiler.
- **The bring-up goes on** (`docs/runtime.md`): natives for Shinobi's work-area pointer, the console's settings (a USA console, NTSC, English, stereo, a VGA cable), its hardware set-up, its allocator (Shinobi's own algorithm over the same guest RAM, so every block lands where it would on the console), its real-time clock's set-up, the C runtime's `memset` and more. The game now runs through the middleware's whole system initialisation, Kamui 2's included, to the GD-ROM file system's initialisation, which is next.
- **The bus** (`recomp/runtime/bus.*`): RAM at `0x8C000000` stays the one-compare fast path; every other access goes to the bus, which handles RAM's other views, the SH-4's store queues (with QACR0/1) and the devices the port maps, and stops on anything else.
- **Hardware under Kamui 2** (`toycommander/src/pvr.*`, `sh4.*`): the PowerVR2's and the system bus's registers, video memory with its 64-bit view, and the SH-4's timer unit (timer 0 free-running, as Shinobi leaves it, counting guest time).
- **The GD-ROM, at the boot ROM's system calls** (`toycommander/src/gdrom_bios.*`): Shinobi's file system (gdFs) and GD-ROM driver (gdd) are now lifted, and the 13 system-call wrappers under them are replaced over the player's disc dump: the drive's initialisation, its state, its version, PIO and DMA reads (the DMA's end raised as the system bus's event 0xA40 at the next call that can take it). gdFs's initialisation and its directory loading now run as on the console.
- **Shinobi's interrupt chains** (`toycommander/src/chain.*`), natively over the same guest records: Kamui 2's two callbacks (events 0x900 and 0x920) and the system bus's events. **Its real-time clock** (`rtc.*`) over the host's local time (the date, the day of the week and the moon's age as Shinobi computes them), **its timer reads** and **its cache operations** (no-ops: the port has no cache).
- **Discovery takes a function-pointer table's entry that points into a known function** as a function of its own when the words beside it point at function entries: gdFs's driver table points at `0x8C0B1FD6`, which `0x8C0B1704` reaches by a branch that is a tail call. 4,306 functions.
- **Interrupts** (`recomp/runtime/guest.hpp`, `toycommander/src/interrupts.*`): the lifter puts a poll at every backward branch (one relaxed load of `rt::g_irq_pending`), where the runtime takes interrupts as the console would at some instruction of a loop: the stack pointer is passed, the handlers run, every register is put back. The graphics chip's level-6 events go to the handler Kamui 2 installed, one per call as it takes them, while IMASK allows; the vertical blank is raised 60 times a second of guest time. An end-to-end test checks a loop takes a pending interrupt once and computes the same result.
- **The tile accelerator's parameter decoder** (`toycommander/src/ta.*`): the stream Kamui 2 writes (32- and 64-byte parameters: lists, polygon and sprite global parameters with their ISP/TSP and texture words, every vertex type for one and two volumes, sprites, modifier volumes) becomes a scene of strips for the renderer, and each list's end raises its event. Unknown parameters stop.
- **The SH-4's DMA controller and channel 2's transfer** (`sh4.cpp`, `pvr.cpp`): Kamui 2's DMA from RAM to the tile accelerator or to texture memory, with its end event.
- **`QILIN_TIMEOUT=<seconds>`**: a run still going by then reports where the guest is and its call chain (exit code 4), for waits on hardware the port doesn't provide yet.
- **pd, bu and the Maple driver lifted** (`recomp/src/layout.cpp`): Shinobi's peripheral library, its memory card file system and their Maple bus driver, spread over several regions of Shinobi, are lifted like gdFs, for the port to provide the Maple bus beneath them; the natives that skipped their set-up are gone. bu's coroutines stay replaced (next).
- **bu's coroutines over host threads** (`toycommander/src/threads.*`): Shinobi's small thread library is lifted but for its two switches, the scheduler's pass and a thread's yield, which run each guest thread on a host thread of its own (16 MB of stack), one at a time, with the guest's own records kept as the guest code keeps them (the pass starts again from the first thread after every yield, as the guest's does). A stop in a guest thread is reported with that thread's registers.
- **Sound RAM and the sound chip's registers** (`toycommander/src/aica.*`): 2 MB of sound RAM and a register file for the AICA, which the audio manager's set-up writes; the chip's ARM is never started.
- **The movie decoder's handler table** (`indirect_targets` in `recomp/src/layout.cpp`): the layout can name an indirect call's targets, and the FPSCR pass follows the mode into them (the TrueMotion decoder's 13 block handlers, called with SZ = 1).
- **CD audio and the table of contents** (`gdrom_bios.cpp`): play and pause, and each area's table of contents from the disc reader's tracks. **The sound driver's start-up handshake** (`aica.cpp`). **The operand cache's address array** accepted as invalidation. The vibration and screen drivers lifted. `QILIN_DUMP` prints guest memory at a stop.
- **Literals the code rewrites** (`Cfg::patched_literals`): a literal-pool word whose address some function loads as a constant is read from memory at run time instead of being folded from the image. The movie decoder patches its dispatcher's offsets that way; with that, the first movie decodes. `qilin cfg` lists them (23); an end-to-end test covers it.
- **FPU transfers lifted for both sizes** when a function's entry modes disagree on SZ: the lifted code picks by FPSCR.SZ at run time (14, in the movie decoder's block handlers, which copy pixels with 8-byte `fmov`s through the XD registers).
- **RAM comparison with the console:** `qilin_dcref --game` runs the game in Flycast's libretro core as a black box and writes its RAM every few frames; `QILIN_RAM_DUMP` writes the port's at a stop (`docs/runtime.md`). The port's heap matches the console's block for block.
- **The sound driver's mailbox** (`toycommander/src/aica.cpp`): the audio manager's commands in sound RAM are taken as the ARM driver takes them (open, close, play, stop, several at once, the sample rate, play with parameters, volume, pan, CD audio's settings), and each voice's read position advances with guest time at its rate. The movies play through at the console's pace, and the game goes on into its attract sequence (`docs/runtime.md`, steps 19-21).
- **Discovery: a return address pushed and popped.** The register state follows r15's offset from entry and the stack slot of the entry PR, so `lds.l @r15+,pr` of that slot restores it and a later `jmp` through a copy is a return (`0x8C061AA0`, the engine's matrix code); unit tests cover it and a slot overwritten before the pop.
- **Discovery: shared tails.** A pointer guess may fall into code other functions branch to (`docs/recompiler-core.md`): 16 more functions, 44 unknown runs instead of 49, 4,322 functions.

### Changed
- **The game's program is `toycommander`** (Toy Racer's `toyracer`), no longer `qilin_run`, built with `-DQILIN_TOYCOMMANDER_BOOT=<1GUTH.BIN or the .cue>` (`-DQILIN_TOYRACER_BOOT`) in place of `-DQILIN_GAME_BOOT`. Its window, data folder (`qilin/<game>`) and settings file are each game's own.
- **The shared code moves to `dreamcast/`** (toward one repository for Toy Commander and Toy Racer, a program for each): the hardware the port provides, the renderer, sound, the Maple bus, the settings file and menu, with no guest addresses, in namespace `dreamcast`; what a game's program gives it is `dreamcast/src/game.hpp`. Toy Commander's own start-up and replacements stay in `toycommander/src/`. The tests are `dreamcast_render_test` and `dreamcast_settings_test`.
- **The port's GD-ROM drive reports version 1.00** (`gdrom_bios.cpp`): above it, gdFs's CD audio calls take a second path (command 36, the drive's state, after a play; a new play rather than command 23 to go on from a pause); at 1.00, a revision gdFs supports too, they use play, pause and go on (20, 22, 23), which the port answers.
- **The game now runs past the middleware's system initialisation into `main`'s own start-up** and its first frames' set-up, through the lifted peripheral server, to bu's initialisation, which starts a coroutine.
- **Graphics: Kamui 2 is lifted and the port replaces the hardware under it** (the PowerVR2's registers, the tile accelerator's parameter stream, video memory) rather than Kamui 2's API. Without symbols, telling Kamui 2's functions apart inside the interleaved middleware proved unreliable, and Kamui 2 is the code that knows how its own calls become hardware commands: the parameter stream it writes is a small, documented format to decode into Vulkan 1.3 draws. The interrupt registration (`0x8C085E16`) is the one Kamui 2 function replaced.
- **The stop report ends with the guest call chain**, read from the return addresses saved on the stack; `QILIN_STACK=1` dumps the stack too.
- **Three rules from ToyRacer--QilinRecomp's core**, which started from this one and found them on its boot file (`docs/recompiler-core.md`), each with unit and end-to-end tests:
  - a `jmp` to a constant address that the function's other paths reach too is a far branch inside the function, lifted as a `goto`, not a tail call. `0x8C090B1C` has 6; two of its labels had been taken for functions, so the build has 4,305 functions and 2,932 lifted. Nothing else in the lifted code changes, and `qilin_run` stops where it did;
  - a pointer guess is thrown out when a function with a compiled prologue contains it and nothing else supports it (none in this build);
  - `bra` to itself, the code's fatal-error stop, is lifted as `rt::hang`, a stop of its own kind, not as an empty loop (one, at `0x8C087AD0`). `qilin cfg` counts branches by register, and its JSON lists them.
- **The GD-ROM's sub-channel command** (34, `gdrom_bios.cpp`): the drive's audio status and the play position as Q-channel data (format 1, 14 bytes), which Toy Racer's menu polls through gdFs. Written from ToyRacer--QilinRecomp's bring-up; the position stands still until the mixer plays CD audio.
- **The first pictures** (`docs/runtime.md`, "The renderer"): a Vulkan 1.3 renderer of the tile accelerator's scenes (`toycommander/src/renderer.cpp`, the shaders in `toycommander/shaders/`), with the PowerVR2's texture formats decoded from video memory (`texture.cpp`), shown in an SDL3 window at each STARTRENDER (`video.cpp`). The game's start-up logos are drawn. Modifier volumes, fog and the translucent list's sorting are still to come; the renderer names each once when a scene asks for it.
- **The host layer** (`host/`): the sister projects' window, Vulkan device, display (picture scaling, the CRT look), sound output and data folder, from PunchOutWii--QilinRecomp, with the game's name in place of Punch-Out's. SDL3, the Vulkan headers and volk are fetched and pinned at configure time as there. `tools/build_shaders.py` compiles the shaders to the committed `shaders.inc` files; CI checks they are current.
- `QILIN_HEADLESS`, `QILIN_SCALE` and `QILIN_SHOT` for the bring-up; `toycommander_render_test`.
- **Translucent polygons sorted by depth** in the hardware's auto-sort mode (ISP_FEED_CFG bit 0 clear, as Toy Commander sets it): the renderer draws the translucent list's triangles from the farthest to the nearest.
- **Cheap shadows**: the opaque modifier volumes, in SHADOW_SCALE's cheap-shadow mode (bit 8, as Toy Commander sets it), darken the polygons that take shadows inside them by the register's low byte, through the stencil (a depth/stencil attachment now: D32 with S8, or D24 with S8 where a device lacks it), each volume resolved on its own so overlapping ones don't cancel. The toys' shadows on the kitchen table are drawn. Translucent modifier volumes are still named once and not drawn.
- **Shadows on translucent polygons**: the translucent modifier volumes, tested pixel by pixel in the fragment shader at each translucent layer's own depth (the volumes in a storage buffer, each with its bounds on screen).
