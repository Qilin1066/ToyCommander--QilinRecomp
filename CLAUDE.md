# CLAUDE.md

Static recompilation of **Toy Commander** (Dreamcast, USA: `MK-57020`, `V1.022`) to native code. Same requirements and scope as the sister projects Qilin1066/GBTGhoulies--QilinRecomp, PunchOutWii--QilinRecomp, RhythmHeavenFever--QilinRecomp (Beat the Beat) and ApbArcade--QilinRecomp (the owner's instruction, 2026-11-21: "exact same as the other projects", down to the settings menu). When a design question here is undecided, do what they did; BeatTheBeat's `CLAUDE.md` has the longest list of lessons.

## Requirements (non-negotiable)

- **Efficiency first, then accuracy, and fail loudly.** Never paper over an unknown: stop with a clear error (exit codes, CMake `FATAL_ERROR`, later `rt::Stop`).
- **C++23** everywhere: recompiler, runtime and generated code.
- **Vulkan 1.3 only** for graphics. No OpenGL, D3D or Metal backends (macOS goes through MoltenVK).
- **Static recompilation only.** No interpreter, JIT or emulator at run time, not even as a fallback. That includes the sound driver's ARM code: the audio manager is replaced above it.
- Targets: 64-bit **Windows, Linux, macOS** on **x86-64 and ARM64**. The low-end reference is ARM boards like the **Raspberry Pi 4**. No 32-bit.
- Compiler minimums: GCC 14, Clang 19, Apple Clang (Xcode 16), MSVC 2022 17.10.
- **Everything unarguably legal** (the owner, 2026-11-21: "i want everything unarguably legal"). No GPL code, tables or constants from others (no Dreamcast emulator's, not QEMU's), even though this project is GPL-3.0 itself: they may be run as black boxes, never read into this code, and their outputs never become tables here (so `fsca` computes its values rather than taking Flycast's). No Dreamcast BIOS anywhere: tools that boot the console use an emulator's own BIOS replacement. Hitachi's and Sega's documents are cited by title, not linked, quoted or included. Keep dependencies to the fewest possible; third-party libraries (SDL3, Vulkan headers, Dear ImGui for the menu, when they arrive) are permissive and handled as the sister projects handle them.
- Never commit game data or anything derived from it: disc images, `1GUTH.BIN`, extracted files, listings, `gen/`, `cfg.json`, symbol lists made from the binary. These are gitignored.

## Layout

- `recomp/src/`: `gdrom` (Redump cue/bin reader, bootstrap, ISO 9660), `bootfile` (loader, known-build SHA-256), `sha256`, `decoder` (SH-4, table-driven, X-macro `QILIN_SH4_OPS`), `cfg` (function discovery, constants, switches, tail calls, coverage; `cfg_report.cpp` is its text and JSON), `layout` (the supported build's regions, with plans), `hwaccess` (hardware accesses at constant addresses), `fpmode` (FPSCR mode per FPU instruction, interprocedural, per entry-mode context), `lifter` (one function to C++) and `lift_output` (`qilin lift`'s files), `main.cpp` (the `qilin` CLI).
- `recomp/runtime/`: `guest.hpp` (context, memory, helpers; header-only runtime code), `dispatch.cpp` (calls through the function table), `memory.*` (the 4 GB reservation), `bus.*` (everything but RAM's main view: the other views, the store queues, mapped devices), `system.*` (the registry of natives, `rt::replaced`, `call_guest`, the stop report). No `std::format` in any of it.
- `toycommander/src/`: `qilin_run` (`main.cpp`), the native start-up (`boot.cpp`), the native replacements (`natives.cpp`), Shinobi's allocator (`heap.cpp`), the hardware the port provides (`pvr.cpp`: the PowerVR2's registers and video memory; `sh4.cpp`: the timer unit; `clock.cpp`: guest time). Built only with `-DQILIN_GAME_BOOT=<1GUTH.BIN>`; `docs/runtime.md` has the design and the bring-up log. `gdrom`, `bootfile` and `sha256` are runtime code too (target `qilin_disc`): no `std::format` there.
- `host/`: the window, Vulkan 1.3 device, display, sound output and data folder, the sister projects' host layer (PunchOutWii--QilinRecomp's `host/`, with the game's name from `QILIN_APP`/`QILIN_APP_TITLE`). `toycommander/src/renderer.cpp` (the tile accelerator's scenes in Vulkan), `texture.cpp` (the PowerVR2's texture formats), `video.cpp` (the renderer and window joined to STARTRENDER); `toycommander/shaders/` compiled by `tools/build_shaders.py` into the committed `shaders.inc` (run it after editing a shader; CI checks). `toycommander/tests/render_test.cpp`: the decoder and a headless scene.
- `recomp/tests/tests.cpp`: unit tests (`ctest`), no game files. `lift_programs.hpp` (a small assembler and synthetic programs), `lift_gen.cpp` (lifts them at build time), `lift_run.cpp` (runs the lifted code against reference results): the end-to-end lifter tests, which make CI compile generated code with every compiler. `difftest/`: the differential test (`gen.cpp` lifts random encodings of every lifted instruction at build time, `ref.cpp` is the reference interpreter, separate from the lifter, `run.cpp` compares everything). After changing the lifter, run it; a planted bug must fail it (keep the programs able to catch slot-ordering bugs: a slot must change what its branch reads).
- `tools/check/verify_decoder.py`: the decoder against Capstone, the whole encoding space.
- `tools/dcref/`: `qilin_dcref`, the FPU's approximate instructions against Flycast's libretro core run as a black box (`fetch.sh` downloads it outside the repo; `-DQILIN_DCREF=ON -DQILIN_DCREF_DIR=<folder>`; Linux x86-64, Mesa EGL surfaceless).
- `docs/`: design and results. Keep them current. `roadmap-and-design-targets.md` is the roadmap; `disc-analysis.md` the disc and boot file; `code-analysis.md` the layout, the libraries and the lifted/replaced boundary; `recompiler-core.md` the loader, disc reader and decoder, and what comes next; `prior-art.md`; `naming.md`.

## Build and check

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DQILIN_WERROR=ON
cmake --build build --parallel
ctest --test-dir build --output-on-failure
python3 tools/check/verify_decoder.py --qilin build/qilin     # pip install capstone; 0 unexplained differences
build/qilin disc path/to/game.cue
build/qilin extract path/to/game.cue --out extracted          # outside the repo, or in an ignored folder
build/qilin info extracted/files/1GUTH.BIN                    # exit 0: the supported build
build/qilin cfg extracted/files/1GUTH.BIN                     # 4,322 functions (0.3 s, two passes)
build/qilin coverage extracted/files/1GUTH.BIN                # exit 0: 0 unknown bytes in lifted regions; 44 unknown runs elsewhere
build/qilin suspects extracted/files/1GUTH.BIN
build/qilin hwaccess extracted/files/1GUTH.BIN                # 76 functions, none in the game
build/qilin fpmode extracted/files/1GUTH.BIN --list           # 0 unproven FPU instructions in the game and middleware; 4 middleware problems (known, docs/code-analysis.md)
build/qilin lift extracted/files/1GUTH.BIN --out gen          # 3,350 lifted (all 1,259 of the game's), 1 not (exception set-up, to replace); gen/ is ignored, never commit it
cmake -S . -B build -DQILIN_GAME_BOOT=extracted/files/1GUTH.BIN && cmake --build build --target qilin_run
build/qilin_run path/to/game.cue                              # exit 3 with a report: what to write next
build-dcref/qilin_dcref <folder>/flycast_libretro.so          # the approximate FPU instructions against the emulator (optional tool)
```

Before a milestone commit, all of these must hold: tests pass, warnings are clean (`QILIN_WERROR`), the decoder check has 0 unexplained differences, and (once they exist) generated code is warning-free under GCC, Clang and MSVC and the differential test has 0 unexplained mismatches.

## Known facts worth not rediscovering

- The boot file is `1GUTH.BIN` ("Guth" is the working title, Gutherman): SHA-256 `ee68a326da964fec5892b7226311f2293fd3a0bbf5bac496ec82991964d49bbd`, 748,444 bytes, loaded at `0x8C010000`, ending at `0x8C0C6B9C`, entered at its first byte. No header, sections or symbols.
- The entry code sets the cache control register and jumps to `0x8C0B0340` (Shinobi's start-up), which calls the game's `main` at `0x8C02796A`. The layout is in `recomp/src/layout.cpp`, its evidence in `docs/code-analysis.md`: game `0x8C010080`–`0x8C0495B8` (lifted, 0 unknown bytes: keep it so); middleware `0x8C0495B8`–`0x8C09F5B6` (engine, audio manager, Kamui 2, `kmdk`, C runtime, interleaved object by object: attribution by range does not work, and spreading labels along call edges was tried and is too noisy); data `0x8C09F5B6`–`0x8C0B0340`; Shinobi `0x8C0B0340`–`0x8C0C5690` with three data blocks inside, replaced but for the libraries lifted over hardware the port provides: gdFs (`0x8C0B13D4`–`0x8C0B3288`) and gdd (`0x8C0BD264`–`0x8C0BDB14`); pd, bu and the Maple driver, in several regions (`layout.cpp`); Shinobi's data to the end.
- The game never touches hardware (`qilin hwaccess`) and calls Shinobi directly from only 3 sites: the runtime's work is replacing Shinobi and the middleware's hardware-facing parts.
- bu's thread library switches by `setjmp`/`longjmp` of every register (`0x8C09CDCC`/`0x8C09CD58`): its pass and yield are natives running each guest thread on a host thread (`threads.cpp`), one at a time; anything else that saves and restores a context like that needs the same.
- Code rewrites its own literal pools: the movie decoder patches its dispatcher's offsets (`0x8C09F320`–`0x8C09F326`) at run time. Discovery marks a literal as patched when a function loads its address as a constant (`Cfg::patched_literals`), and the lifter reads those from memory; anything else rewriting code would show as a difference between the console's RAM and the boot file (`qilin_dcref --game`, `docs/runtime.md`). FPU transfers whose entry modes disagree on SZ are lifted both ways and choose by FPSCR.SZ at run time.
- `qilin_dcref --game` runs the game in Flycast (black box, its own BIOS replacement) and dumps RAM every few frames; `QILIN_RAM_DUMP` dumps the port's at a stop. The port's heap is the console's block for block, so addresses compare directly.
- Interrupts are taken only at lifted loops' backward branches (`QILIN_POLL_IRQ`, `guest.hpp`); a wait that never ends usually means an event the port doesn't raise yet: `QILIN_TIMEOUT=20` names the loop.
- The boundary, as the bring-up drew it: where a Sega library is software over a narrow interface, the library is lifted and the interface is the port's. Kamui 2 over the PowerVR2's registers and parameter stream; gdFs and gdd over the boot ROM's GD-ROM system calls (`toycommander/src/gdrom_bios.cpp`: frame address = the disc reader's sector + 150; commands complete when sent; a DMA read's end is raised as the system bus's event 0xA40 at the next call that can take it). Shinobi's other parts are natives, over the same guest RAM and state as the guest code where anything outside Shinobi could read it (the allocator, the interrupt chains).
- Function discovery's results and rules are in `docs/recompiler-core.md`. Things that cost time: literal pools contain dead entries nothing loads, and they decode (float constants look like FPU instructions), so a guessed function must not run on into known code; pointer candidates are tried in address order, so a bogus one just before a real function used to swallow it (fixed by rejecting a guess that runs into another candidate's start); SHC tail-calls with `bra` (and `bt`/`bf`), which absorbed the callee into the caller until v0.3.0 (now: a branch to a prologue start or a known entry is a tail call, and the analysis iterates to a fixed point); float constants are read through `mova` + `fmov @r0`, not PC-relative loads, so they need the constant-address literal rule; the layout's data regions must still be scanned for function pointers (the pointer tables are there); 784 functions are unreferenced by any address in the image (dead code: don't lift them by default).
- Three rules came back from Toy Racer (ToyRacer--QilinRecomp, the same engine; keep the two cores in step): a `jmp` to a constant address the function's other paths reach too is a far branch inside it (`computed_branches`), not a tail call (here: 6 in `0x8C090B1C`, 2,427 instructions; the two "functions" at `0x8C0921C8` and `0x8C0921E0` were its labels); a pointer guess is thrown out when a function with a compiled prologue contains it and nothing else supports it (`Analysis::find_evictions`; none here); `bra` to itself is the code's fatal-error stop, lifted as `rt::hang` (one, at `0x8C087AD0`), never as an empty loop.
- `0x003B` is not in the decoder's set but the image has four, in `0x003B ; rts ; nop` stubs that real code calls (`0x8C099470`): debugger hooks, to be replaced natively. Stubs with `trapa #2` sit beside them.
- The lifter: a delay slot's branch reads its condition, target and PR before the slot runs; every call checks `c.ret` against the address after its slot; `trapa` never reaches it (discovery rejects functions with one). Every label target must be an emitted instruction, not a slot. Tests that break `div1`'s Q update or a generated switch case must fail: keep the end-to-end tests able to catch that.
- The lifter's FPU: the current bank in `float` locals, the back bank in `c.xf`; DRn = FRn (high) : FRn+1; a 64-bit fmov puts FRn at the lower address. Denormals are flushed by the host's mode (`rt::host_fp_setup()`: FTZ+DAZ, ARM64 FZ), which every thread running lifted code must call; generated code needs `-ffp-contract=off`. NaN bit patterns from arithmetic are the host's, and FPSCR's cause/flag bits read as 0: both for the differential test to confirm. `fpmode` counts only calls from analysed code as calls: a function called only from replaced code starts in the default mode (missing this skipped `main`'s subtree until v0.6.0).
- SR is modelled (`guest.hpp`'s `set_sr`): T, S, Q, M in locals, the rest in `c.sr` with MD = 1, RB = BL = FD = 0 fixed; `ldc` may change IMASK only. The session's disc dump here has only the data tracks; a stand-in folder with blank audio tracks of the right sizes (local, never committed) lets the disc reader open it.
- `0x8C04EEE0` is the C runtime's `memset` through the store queues (`docs/code-analysis.md`): a native replacement is needed early in bring-up. `mov.l Rn,@-Rn` stores the value before the decrement (Flycast agrees).
- The call idiom assumption (calls preserve r8–r15) is only the compiler's convention: see the note in `cfg.hpp` before the lifter devirtualises anything. r0–r7 are no longer assumed clobbered by every call: a call clears only the scratch registers its callee can write (computed per callee, transitively).
- Hand-written library code calls with `lds rN,pr ; jmp @rM` and returns with `jmp @r2` through a saved PR: the CFG tracks PR for this (`call_returns`, `jmp_returns`), and the stack slot a prologue pushed it to (`sp`, `pr_slot` in `RegConstants`: a pop of that slot restores it). The lifter must handle both.
- The port's GD-ROM drive reports "GDC Version 1.00": above that gdFs's multi-sector reads send command 36 first (not answered).
- The FPU: the default mode is `0x00040000` (round to nearest, **DN = 1: denormals flushed to zero**, single, 32-bit transfers, bank 0). The game never leaves it. FR is handled by swapping two bank arrays on `frchg` (never needs to be known); the engine really runs in bank 1 after some matrix calls (`0x8C06166C` returns in the other bank). The dispatcher `0x8C09F2AC` calls its table handlers with SZ = 1: the layout names them (`indirect_targets`), and the mode pass follows the mode into them. How the pass got to its design (and the dead ends: per-function defaults, symbolic entry summaries) is in `docs/recompiler-core.md`; don't go back to them.
- The middleware's attribution: decided in v0.4.0 to drive it from bring-up (lift the middleware, stop on hardware, replace upward). Shared global variables group functions (audio core = one group; Kamui 2 spans the whole middleware); constant-section order confirms link order; padding means nothing.
- The dump is Redump-style: `.cue` plus 15 `.bin` tracks. Tracks 1–2 single density; track 3 (sector 45000) holds the bootstrap and directories; tracks 4–14 are the music (CD audio); track 15 (index 1 at 377422) holds all 81 files. ISO sector numbers are absolute disc sectors.
- Libraries in the boot file: Shinobi 1.61, Kamui 2 (16,3,0,0) with `kmdk`, the audio manager (`am*`/`ac*`, loads `AUDIO64.DRV`, ARM code), a TrueMotion 2X AVI player, No Cliché's engine with its script interpreter. No Windows CE.
- Movies: AVI, `TM2X` video, Duck DK4 ADPCM sound (format tag 0x61), 640×480; `60HZ_` and `50HZ_` versions.
- SH-4 points that shape the lifter: delay slots; PC-relative literal pools inside the code (`mov.l` rounds the PC down to a multiple of 4, `mov.w` doesn't); calls are usually `mov.l pool,rN` + `jsr @rN`; FPU instruction meaning depends on FPSCR.PR/SZ/FR, and the code does switch them (`fschg`, `frchg` both appear); `fmac`, `fsca`, `fsrra`, `fipr`, `ftrv` have no documented exact results: with no console at hand, the owner asked (2026-11-21: "i dont have a dreamcast to hand. why dont you install a dreamcast emulator for your testing") for an emulator to test against. Their definitions are our own (`guest.hpp`), chosen with `qilin_dcref` against Flycast: all agree on every input without a denormal except `fsca` (Flycast's own table, within 2⁻²³; never copy it). Flycast keeps denormal operands where the manual's DN = 1 zeroes them: the port follows the manual.
- Capstone 5's SH-4 mode also decodes SH-2A/SH-4A instructions and lacks `fipr`, `fcnvds`, `fcnvsd`: both are reviewed differences in `verify_decoder.py`. Unicorn has no SuperH: the differential test uses a reference of our own, as the sister projects do.
- The decoder's table throws at start-up if a form leaves a bit undefined or two forms share a word: after editing `kRows`, run the tests; the pinned counts (59,001 valid words, 8,770 delayed branches) change only if the instruction set does.
- SDL3 (3.4.20) won't build its Wayland support with Ubuntu 24.04's headers under the zig toolchain (`WL_KEYBOARD_KEY_STATE_REPEATED`): configure a session's local build with `-DSDL_WAYLAND=OFF -DCMAKE_C_COMPILER=<zig cc wrapper>` (the project has C for SDL3). CI builds it with GCC as Punch-Out's does. Mesa's `mesa-vulkan-drivers` (llvmpipe) gives a session a Vulkan 1.3 device for the headless tests and `QILIN_HEADLESS=1` runs.
- Building where there is no GCC 14 or Clang 19 (a session's Linux container, a Windows PC without LLVM): `pip install ziglang`, then use `python -m ziglang c++` as the compiler (a wrapper script for CMake's `CMAKE_CXX_COMPILER`). GCC 14 and MSVC are then checked only by CI: check CI after pushing. Compiler messages are annotations on the commit (`.github/matchers/compilers.json`).
- GCC's `-Wshadow` also flags a local reusing a file-scope name (Clang's and MSVC's don't), and MSVC's `[[maybe_unused]]` covers only a declaration's first declarator: both bit the sister projects.

## Status (v0.9.0)

- The disc reader, boot file loader, SH-4 decoder (Capstone cross-check: 0 unexplained differences), function discovery (with PR tracking), the build's layout, coverage per region, the hardware profile and the FPSCR mode pass exist, with tests. 4,322 functions, 14 switch tables; the game region has 0 unknown bytes; every FPU instruction of the game and middleware has a proven mode. The lifter lifts 3,350 functions: all 1,259 of the game's, the middleware's and Shinobi's gdFs and gdd (SR is modelled; 1 exception set-up function left, to be replaced); its output compiles warning-free, and the end-to-end tests run lifted synthetic programs under every CI compiler. The differential test (every lifted instruction against a reference interpreter of our own, `recomp/tests/difftest/`): 248,016 runs, 0 mismatches. `qilin_run` boots the lifted game through the middleware's whole system initialisation (Kamui 2's lifted, against the port's PowerVR2 registers, video memory and timer 0; Shinobi's allocator natively, block for block as the console's; gdFs and gdd lifted over the boot ROM's GD-ROM calls on the disc dump) into `main`'s own start-up and its frame loop (Kamui 2's DMA to the tile accelerator, whose parameter stream is decoded into a scene; interrupts at loops' backward branches, Kamui 2's handler, a 60 Hz vertical blank), plays the movies (the sound driver's mailbox answered natively) and runs the attract sequence; no window, input or sound output yet (`docs/runtime.md` has the log).
- CI was green on v0.1.0 on all six jobs; check it after each push.
